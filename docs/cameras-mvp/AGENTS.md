# Cameras MVP 文档维护约束

## 单一事实源

- `README.md` 只维护 MVP 范围、冻结决策和交付顺序。
- `01-foundation/README.md` 只维护跨切片公共契约。
- `01-foundation/execution-plan/README.md` 是实施状态、步骤和验证命令的唯一所有者。
- `02–09` 只写对应切片独有的契约差异、行为和验收。
- 精确 HTTP Schema 在 Foundation 步骤 6 后以 `contracts/openapi.json` 为准。

引用公共规则时使用链接，不复制或改写原文。不得在多份文档中维护完成进度、全局 DoD、
Query Key、完整敏感数据边界、固定排序、Path 命名或占位 Router 生命周期；端点文档只声明
自己必须携带的安全响应头。

## 修改流程

1. 先确定事实所有者，只修改所有者正文。
2. 检查引用方是否仍准确；必要时更新链接或一句差异说明，不粘贴公共规则。
3. API 形状变化时同步更新后端 Schema、OpenAPI、生成类型和 Fixture。
4. 跨切片决策变化时更新 MVP 冻结决策；实现进度只更新执行计划。
5. 修改后检查相对链接、重复规则和 Markdown 格式。

不要添加手工“更新日期”；Git 历史承担时间记录。不要为了让每篇文档看似自包含而恢复
“范围/Fixture/独立验收/Definition of Done”四套重复章节。

## 保真要求

压缩或重构时不得丢失无外键事务与锁顺序、严格 UUID、敏感 CameraDetail、MediaMTX 严格
布尔状态、完整分页快照、配置降级、提交后尽力清理、各类超时、固定排序/字面搜索和播放器
资源释放条件。若这些规则需要迁移，必须先写入新的唯一所有者，再删除旧文本。
