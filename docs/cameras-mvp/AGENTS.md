# Cameras MVP 文档维护约束

## 单一事实源

- `README.md` 维护 MVP 范围、实现状态、冻结决策和全局完成标准。
- `01-foundation/README.md` 维护已经落地的跨切片公共契约和验证方式。
- `02–11` 只维护对应切片独有的目标行为与验收，不重复公共规则。
- 精确 HTTP Schema 以 `contracts/openapi.json` 为准；代码和自动化测试优先于文字状态。

引用公共规则时使用链接，不复制全文。不得在多份文档中维护完成进度、Query Key、完整敏感
数据边界、固定排序、Path 命名或占位 Router 生命周期。

## 修改流程

1. 先核对当前代码、迁移、OpenAPI 和测试，再修改对应事实所有者。
2. 功能实现后更新根状态表和该切片的状态说明，不增加执行过程或测试通过数量。
3. API 形状变化时同步后端 Schema、OpenAPI、生成类型和 Fixture。
4. 跨切片决策变化时更新 MVP 冻结决策；公共实现约束变化时更新 Foundation。
5. 修改后检查相对链接、重复规则和 Markdown 格式。

不要添加手工更新时间、阶段总结或提交记录。Git 历史和 CI 承担过程记录。

## 保真要求

压缩或重构时不得丢失无外键事务与锁顺序、严格 UUID、敏感 `CameraDetail`、MediaMTX 严格
布尔状态、完整分页快照、配置降级、提交后尽力清理、固定排序/字面搜索和播放器资源释放条件。
需要迁移规则时，先写入新的唯一所有者，再删除旧文本。
