# 执行计划

本目录只保存尚未完成、可以直接交给开发者执行的工作。当前计划：

- [Backend 日志改造](backend-logging/README.md)
- [Cameras MVP 剩余能力](cameras-mvp/README.md)

## 计划内容

计划应写清目标、非目标、受影响模块、依赖、实现步骤、验收行为和验证命令。计划可以引用
`modules/` 中的当前事实，但不要复制长期规则；代码变化后先重新核对当前实现。

## 完成规则

一个计划只有在代码和必要测试完成后才能移除。移除前必须：

1. 把当前能力、接口、配置、故障和排障信息写入对应 `modules/` 文档。
2. 在 `changes/` 新增变更记录，说明使用者需要知道的影响。
3. 必要时更新总体架构、产品范围或 Design System。
4. 只在形成跨模块长期取舍时新增 `decisions/` 记录。

完成的 plan 不在仓库中归档，也不改名为“已完成”。Git 历史负责保存执行细节，`changes/` 负责
提供可阅读的交付历史。
