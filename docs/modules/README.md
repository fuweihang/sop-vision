# 模块文档

这里保存已经实现、需要在后续开发中持续维护的能力。目录尽量与代码中的业务模块或清晰的产品能力
对应，不按单次项目、版本号或迭代名称建目录。

## 当前模块

- [Cameras](cameras/README.md)：Camera 配置、媒体运行态、后台恢复和创建流程。

## 模块目录应包含什么

每个 `modules/<module>/README.md` 作为入口，至少回答：

- 当前已经能做什么，哪些能力还不能做。
- 模块拥有的数据、对外接口及与其他模块的边界。
- 关键业务规则、失败与降级行为、安全注意事项。
- 运行配置、排障入口和验证命令。
- 更详细的主题文档链接，以及尚未完成计划的链接。

实现细节较多时按稳定主题拆文件，例如 `data-model.md`、`api.md`、`media-integration.md`。不要按
“第一阶段”“任务 03”继续拆长期文档，因为任务编号会结束，而能力会继续演进。

模块文档描述当前行为。未来行为写入 `docs/plans/`；某次交付的历史影响写入 `docs/changes/`。
