# Detector 产品需求基线

> 状态：需求确认中
>
> 需求依据：[`docs/prototype/v1.4.html`](prototype/v1.4.html)
>
> 当前版本：仅定义 `Cameras` 与 `Detection Tasks`
>
> 更新日期：2026-08-14
>
> 说明：本文总结产品行为和验收口径，不规定 Detector 内部技术实现；原型中的模拟数据、延时和 Hash 路由不等同于生产实现。

## 1. 产品定位

SOP Vision 是企业内部的视觉检测平台。“SOP”是项目定位，不代表系统需要实现多步骤流程编排。

当前核心能力是：

1. 管理物理摄像头及其多路 RTSP 视频源。
2. 为某一路摄像头源创建检测任务。
3. 每个检测任务绑定一套算法和一份算法参数。
4. 配置算法动态参数和算法规定的 ROI。
5. 管理任务的启动、停止、重载、重启、删除和实时运行状态。
6. 预览实时检测画面、检测框和 ROI 叠加层。

核心关系：

```text
Camera 1 ── N CameraSource
CameraSource 1 ── N DetectionTask
DetectionTask N ── 1 Algorithm
```

约束与说明：

- 同一台摄像头可以配置多路源。
- 同一路 CameraSource 可以被多个 Detection Task 绑定。
- 同一个 Camera 可以存在多个 Detection Task。
- 每个 Detection Task 只绑定一路 CameraSource 和一套 Algorithm。
- 同一路 CameraSource 被多个任务使用时如何复用连接、解码或帧数据，当前阶段不做具体设计。

## 2. 当前版本的信息架构

管理后台的侧边栏当前只包含两个一级菜单：

1. `Cameras`
2. `Detection Tasks`

页面以桌面端为主要使用场景，同时需要支持窄屏和浏览器缩放后的响应式重排：

- 桌面端侧边栏支持折叠为图标栏。
- 窄屏下侧边栏变为抽屉，通过遮罩关闭。
- `Control/Command + B` 可切换侧边栏。
- 列表、详情双栏、表单和 ROI 编辑器随可用宽度逐级改为单列。
- 不得通过页面级横向滚动维持桌面布局。

历史结果和异常证据未来通过新的同级侧边栏菜单访问，但当前版本：

- 不设计该菜单。
- 不显示进入历史结果或异常证据的路由按钮。
- 不实现历史查询页面与异常证据页面。

## 3. Cameras

### 3.1 业务对象

`Camera` 表示一台物理摄像头，建议包含：

- `camera_id`
- 摄像头名称
- IP 地址
- RTSP 端口
- 用户名
- 密码
- 厂商，首期重点支持海康摄像头
- 默认预览源
- 启用状态
- 创建时间、更新时间

`CameraSource` 表示摄像头的一路通道或码流，建议包含：

- `source_id`
- `camera_id`
- 源名称，例如“通道 1 主码流”
- URL 后缀
- 系统生成的完整 RTSP 地址
- 是否为预览源
- 启用状态
- 连接状态
- 可探测的视频信息，例如分辨率、编码格式和 FPS

### 3.2 新增摄像头

新增摄像头时填写：

- 摄像头名称
- IP 地址
- RTSP 端口
- 用户名
- 密码
- 至少一路 URL 后缀

字段校验：

- 上述基础字段均为必填。
- RTSP 端口范围为 `1–65535`，新建时默认 `554`。
- 每一路视频源的名称和 URL 后缀均为必填。
- 至少保留一路视频源，且必须指定一路默认预览源。
- URL 后缀开头多余的 `/` 在生成地址时移除。

系统根据基础信息与每一路 URL 后缀生成 RTSP 地址：

```text
rtsp://{username}:{password}@{ip}:{port}/{url_suffix}
```

以海康摄像头为例：

```text
Camera：车间入口

├── 通道 1 主码流
│   └── Streaming/Channels/101
├── 通道 1 子码流
│   └── Streaming/Channels/102
└── 通道 2 主码流
    └── Streaming/Channels/201
```

### 3.3 多路源管理

- 一个 Camera 可以新增、编辑和删除多路 CameraSource。
- 每一路源具有独立名称和 URL 后缀。
- URL 后缀应允许海康标准路径，也允许用户输入厂商自定义路径。
- 应避免同一 Camera 下出现完全重复的 URL 后缀。
- 删除已被 Detection Task 绑定的源时，系统必须阻止删除并说明关联任务。

### 3.4 预览源

- 新增 URL 后缀后，通过单选框选择其中一路作为摄像头预览源。
- 编辑摄像头时可以重新选择预览源。
- 同一 Camera 同时只能有一路预览源。
- Camera 至少存在一路启用源时，应有且只有一路预览源。
- 修改预览源只影响 Cameras 中的默认预览，不自动修改 Detection Task 已绑定的 CameraSource。
- 预览使用系统生成的 RTSP 地址接入，前端播放链路仍通过平台的视频服务提供。
- 详情页允许开始或停止浏览器端预览；该操作不改变摄像头、视频源或检测任务的启用状态。

### 3.5 密码与 RTSP 地址展示

- RTSP 用户名、密码和完整地址不做加密或脱敏处理。
- 后端数据库明文保存用户名、密码和完整 RTSP 地址。
- API 可以原样返回用户名、密码和完整 RTSP 地址。
- 前端可以原样展示和编辑用户名、密码及完整 RTSP 地址。
- 当前版本不对日志中的 RTSP 用户名、密码或地址提出脱敏要求。

### 3.6 Cameras 当前版本操作

- Cameras 默认页使用卡片展示各 Camera，不在列表页同时展开详情。
- 右侧主内容 Header 居中显示当前页面的面包屑，不承载操作按钮。
- Cameras 卡片列表与 Header 之间设置独立操作栏：搜索框占满剩余宽度，右侧为“添加摄像头”。
- 搜索支持按摄像头名称或 IP 过滤卡片。
- 卡片展示默认预览画面、聚合连接状态、IP/端口、在线源数量和关联任务数量。
- 摄像头聚合状态至少包括：全部源在线时“在线”、部分源异常时“异常”、全部源离线时“离线”。
- 点击 Camera 卡片后进入该 Camera 的独立详情视图。
- Camera 详情视图提供明确的“返回 Cameras”操作，返回卡片列表。
- 新增摄像头。
- 查看摄像头列表。
- 查看摄像头详情。
- 编辑摄像头基础信息。
- 新增、编辑和删除 CameraSource。
- 选择默认预览源。
- 预览默认源。
- 检查每一路源的连接状态。
- 删除未被任务引用的视频源。

> v1.4 原型没有摄像头删除入口，也没有完整实现“删除被任务引用的视频源时阻止删除”的约束；两项均需在正式实现前确认并补齐。

## 4. Detection Tasks

### 4.1 任务定义

Detection Task 表示一路摄像头源应用一套算法的运行配置。

创建或编辑任务需要以下字段：

- 任务名称
- 任务描述，选填，最多 100 个字符
- 摄像头
- 视频流
- 算法
- 算法参数
- 算法要求的全部 ROI

任务还需要由系统维护：

- `task_id`
- 配置版本
- 实际运行状态
- 当前应用的配置版本
- 最近心跳时间
- 最近错误码与错误信息
- 创建时间、更新时间

### 4.2 摄像头与视频流选择器

v1.4 使用两级联动下拉框选择一路 CameraSource：

```text
摄像头：车间入口 · 192.168.1.64
视频流：通道 1 主码流 · 在线
```

选择规则：

- 先选择 Camera，再加载该 Camera 下的视频流。
- Camera 选项显示名称和 IP。
- 视频流选项显示 CameraSource 名称和当前连接状态。
- Camera 没有视频源时，视频流选择器禁用且任务不可保存。
- 离线源可以展示，但创建或启用任务前应明确提示其当前不可用。
- 同一个 CameraSource 可以被多个任务选择，当前版本不限制数量。

### 4.3 算法与参数

- 每个任务只能选择一套算法。
- 不同任务可以绑定同一套算法。
- 算法参数由所选算法定义。
- 算法切换后，参数表单应切换为新算法对应的参数定义。
- 参数 schema 至少支持数字、单选和布尔类型；数字参数包含默认值、最小值、最大值、步长和可选单位。
- 新建任务使用算法默认参数；编辑任务回填已保存参数。
- 数字参数超出算法定义范围时禁止保存并指出具体字段及合法范围。
- 保存任务时，后端必须再次校验算法参数。
- 不同算法输出结构不同；具体协议后续专题讨论。
- 输出协议方向暂定为“统一公共字段 + 算法扩展字段”。

建议保留的统一公共字段：

- `task_id`
- `camera_id`
- `source_id`
- `algorithm_id`
- `frame_id`
- `frame_ts`
- `result_type`
- `objects`
- `metrics`
- `attributes`

### 4.4 ROI 配置

- ROI 的数量、`id` 和标签由算法接口定义，用户不能增加、删除或改名。
- 切换算法后，ROI 列表切换为新算法的定义；不沿用不兼容算法的 ROI。
- 用户逐个选择 ROI，在实时画面上绘制不规则多边形。
- 一个有效 ROI 至少包含 3 个顶点；所有算法要求的 ROI 均完成后才能保存任务。
- 绘制中支持撤销最后一点、完成和取消；取消不得覆盖此前已保存的多边形。
- 修改已完成的 ROI 采用整体重绘，不要求在 MVP 中拖动单个顶点。
- ROI 点位以相对画面的归一化坐标持久化，确保随预览尺寸缩放。
- 前端为 ROI 分配可区分的本地显示颜色，并在任务详情的画面下方显示颜色图例。
- 任务详情提供“显示 ROI”开关；该开关只控制 ROI 叠加层，不影响检测框和算法执行。

### 4.5 启用与停止语义

`enabled` 是任务的期望运行状态：

- `enabled = true`：任务应自动运行。系统启动或 Detector 恢复后，应自动启动该任务。
- `enabled = false`：任务不应运行。

任务只通过 `enabled` 控制，不设置任何暂停状态字段：

```text
用户点击“启用/启动” → enabled = true
用户点击“停止”     → enabled = false
```

- 点击“停止”是真正停止任务，同时持久化 `enabled = false`。
- 自动对账只自动启动 `enabled = true` 的任务。
- 系统重启后，只恢复 `enabled = true` 的任务。
- 用户再次点击“启用/启动”时，将 `enabled` 设置为 `true` 并启动任务。

建议将配置状态与运行状态分开：

```text
Desired State：enabled
Actual State：STARTING / RUNNING / RECONNECTING / DEGRADED / STOPPING / STOPPED / ERROR
```

例如：

```text
enabled = true  + runtime_state = RUNNING  → 已启用且正常运行
enabled = true  + runtime_state = ERROR    → 希望运行，但当前运行失败
enabled = false + runtime_state = STOPPED  → 用户已停止任务
```

新建任务保存后默认：

```text
enabled = false
runtime_state = STOPPED
```

用户需要进入任务详情手动启动。编辑并保存已有任务时，不自动改变其 `enabled` 和当前运行状态；新配置是否已被运行实例应用，应通过配置版本或明确状态表达。

### 4.6 任务列表与详情

任务列表：

- 支持按任务名称、描述、任务 ID、摄像头名称、视频源名称、算法名称或算法 ID 搜索。
- 每行展示任务名称、描述、摄像头源、算法、当前状态。
- 无任务和搜索无结果使用不同空状态；无任务时提供创建入口。
- 点击任务行进入独立详情页，并支持通过返回按钮或面包屑回到列表。

任务详情：

- 展示任务名称、可选描述、任务 ID、绑定的摄像头源、算法 ID 和参数摘要。
- 展示实时标注画面、检测结果标签、帧号/时间等实时元数据。
- 展示运行状态；源不可用时应明确显示，不得静默回退到其他源。
- 提供启动/停止、重载、重启、编辑和删除操作。

### 4.7 任务操作

当前版本支持：

- 创建任务。
- 查看任务列表与详情。
- 编辑任务。
- 启用或启动任务，将 `enabled` 设置为 `true`。
- 停止任务，将 `enabled` 设置为 `false`。
- 重载任务配置。
- 重启任务。
- 删除任务。
- 查看当前运行状态、算法检测数据和错误信息。

“重载任务”的语义为：

1. 仅允许对 `enabled = true` 的任务执行。
2. 不终止任务进程和视频连接，重新载入当前已保存配置。
3. 操作期间按钮进入忙碌和禁用状态，防止重复提交。
4. 完成后明确提示成功或错误，并更新当前应用的配置版本。

“重启任务”的语义为：

1. 仅允许对 `enabled = true` 的任务执行重启。
2. 停止当前算法实例和视频连接。
3. 使用当前已保存配置重新启动。
4. 返回新的运行状态或明确错误。

“删除任务”的语义为：

1. 从详情页进入危险操作区。
2. 二次确认框显示待删除任务名称，并明确说明不可撤销。
3. 确认后删除任务配置、返回任务列表，并同步刷新摄像头关联任务数。
4. 正式实现必须明确运行中任务是“先停止再删除”还是“禁止删除”；原型未覆盖失败与并发状态。

## 5. 通用交互与体验要求

### 5.1 导航与状态反馈

- Header 居中显示当前模块及详情层级的面包屑，详情页同时提供显式返回按钮。
- 页面刷新后允许根据路由恢复 Cameras、Camera 详情、Detection Tasks 或 Task 详情。
- 保存、启动、停止、重载、重启、删除和切换预览源后，以可被辅助技术感知的消息反馈结果。
- 耗时操作保持按钮尺寸稳定，展示忙碌状态并防止重复提交。
- 系统提供浅色/深色主题切换，并记住主题与桌面侧边栏偏好。

### 5.2 表单与弹窗

- 所有字段使用可见标签，错误信息指出修复方法，并关联到具体字段。
- 摄像头和任务均在弹窗中新增或编辑；可通过取消、关闭按钮、点击遮罩或 `Escape` 退出。
- ROI 绘制中按 `Escape` 只取消当前草稿，不直接关闭整个任务弹窗。
- 删除任务使用独立的警告弹窗。

### 5.3 可访问性与响应式

- 所有按钮、表单控件和 ROI 列表项可通过键盘访问；MVP 的 ROI 画布点位输入仅要求指针操作。
- 当前项、错误、在线/异常/离线等状态不能只用颜色表达，必须同时提供文字或形状提示。
- 弹窗、警告框、导航、表格和实时状态通知使用对应语义与可访问名称。
- 遵循用户的减少动态效果设置。
- 以 1280×720 为桌面基准，并验证约 640 CSS px（200% 缩放）及 320 CSS px 的内容重排。

## 6. 当前版本不实现

### 6.1 历史结果与异常证据

以下需求保留到后续版本：

- 保存和查询历史检测结果。
- 保存异常事件。
- 录制异常事件前后的短视频证据。
- 使用异常证据支持算法微调。
- 历史结果和异常证据的同级侧边栏菜单。
- 从 Cameras 或 Detection Tasks 跳转到历史/证据菜单的按钮。

当前版本的界面和路由中不得提前显示不可用入口。

### 6.2 测试功能

当前版本不实现：

- “立即测试”操作。
- 使用实时视频进行临时测试。
- 上传或选择保存的视频进行测试。
- 测试运行记录。
- 将测试参数应用到正式任务。

界面中不得显示“立即测试”按钮或相关入口。

### 6.3 多任务共享视频源优化

同一个 CameraSource 可以绑定多个 Detection Task，但当前阶段只确认业务关系，不决定以下技术实现：

- 是否只建立一个 RTSP 连接。
- 是否只解码一次。
- 是否在多个算法任务之间共享帧。
- 如何进行背压、资源隔离和任务调度。

这些问题在 Detector 技术设计阶段根据摄像头数量、算法性能和部署硬件决定。

## 8. 原型与生产实现差距

v1.4 是前端交互原型，以下行为不能直接作为后端实现：

- 原型将任务展示状态简化为“运行中/已停止”，并主要由 `enabled` 推导；生产环境必须使用独立的 Actual State。
- 原型中的重载和重启使用固定前端延时模拟；生产环境需要异步命令、超时、失败反馈和最终状态对账。
- 原型以数组下标引用 CameraSource；生产数据必须使用稳定的 `source_id`，避免增删或排序后任务绑定错位。
- 原型未覆盖接口加载、视频加载、断线重连、无权限、保存失败、命令超时和并发修改。
- 原型直接显示 RTSP 密码和完整 URL，这是当前基线选择，但存在明显安全风险，上线前应再次确认适用环境和审计要求。
- 原型允许选择离线源并保存任务，未实现创建/启动前的阻断或确认提示。
- 原型未处理运行中任务的删除流程，也未实现被任务引用的视频源删除保护。

## 9. 当前仍待讨论

以下内容不影响本轮需求冻结，可在后续专题中确定：

1. 第一批正式算法列表、参数 schema 和 ROI schema 的接口规范。
2. 不同算法的统一结果协议和扩展字段规范。
3. ROI 坐标系、画面旋转/裁剪、分辨率变化时的转换规则。
4. 摄像头源连通性检查的成功标准、刷新频率与超时时间。
5. Detection Task 的 Actual State 映射、实时指标、心跳和错误展示规则。
6. 编辑运行中任务后配置的生效策略，以及配置版本/LKG 回退策略。
7. 重载、重启、停止和删除命令的超时、幂等与并发控制。
8. 离线源在创建和启动任务时采用警告还是阻断。
9. 摄像头删除能力及运行中任务删除策略。
10. 多个任务绑定同一 CameraSource 时的连接和解码复用方案。
11. RTSP 凭据明文保存、传输、展示和日志记录的安全边界。
12. 历史结果、异常事件、证据视频和测试功能的后续版本规划。

## 10. MVP 验收摘要

1. 用户可新增和编辑包含多路视频源的 Camera，并保证始终存在唯一默认预览源。
2. Cameras 列表可搜索，正确展示源健康聚合状态、在线源数和关联任务数；详情可预览并切换默认源。
3. 用户可创建任务，完成 Camera/视频流/算法绑定、动态参数配置和算法要求的全部 ROI；新任务保存后保持停止。
4. Detection Tasks 列表可搜索；详情可展示实时画面、检测数据、ROI 图例、绑定信息和运行状态。
5. 已启动任务可停止、重载或重启；停止任务不能重载或重启，所有操作均有处理中和结果反馈。
6. 用户可编辑任务且不改变其启用状态，可在二次确认后删除任务。
7. 空数据、搜索无结果、字段错误、源不可用、命令失败和连接异常均有明确状态，不出现无反馈操作。
8. 浅色/深色主题、侧边栏折叠、窄屏重排和键盘基础操作符合设计系统要求。
