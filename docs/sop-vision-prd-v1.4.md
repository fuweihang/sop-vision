## 2. 产品概述

### 2.1 产品定位

SOP Vision 是企业内部视觉检测平台。本期围绕两类资源提供管理能力：

1. 物理摄像头及其多路 RTSP 视频源。
2. 绑定一路视频源和一套算法的检测任务。

“SOP”是项目定位。现有需求没有定义多步骤流程编排能力。

### 2.2 本期目标

- 管理 Camera 与 CameraSource 配置。
- 查看摄像头和视频源连接状态，并预览默认视频源。
- 创建、查看、编辑和删除 Detection Task。
- 为任务选择算法、填写算法动态参数并绘制算法要求的 ROI。
- 控制任务启动、停止、重载和重启。
- 查看任务实时标注画面、检测结果摘要和运行状态。

### 2.3 尚未定义的产品目标

以下内容在现有资料中没有定义，不能据此设置验收指标：

- 目标用户角色、组织结构及使用人数。
- 业务成功指标、使用频率和效率提升目标。
- 摄像头、视频源、任务及并发视频的规模目标。
- 可用性、延迟、吞吐量和资源消耗目标。

## 4. 用户与使用场景

### 4.1 用户

现有资料只出现统一的“用户”操作视角，未定义角色差异。管理员、运维人员、算法人员、只读人员是否需要不同权限，均待确认。

### 4.2 核心场景

1. 用户录入一台摄像头及其多路 RTSP 视频源，指定默认预览源。
2. 用户查看摄像头列表、连接状态和默认源预览。
3. 用户选择 Camera、CameraSource 和 Algorithm 创建检测任务。
4. 用户按照算法 schema 配置参数，并完成算法规定的全部 ROI。
5. 用户进入任务详情启动、停止、重载或重启任务。
6. 用户查看实时标注画面、检测结果摘要、ROI 和任务配置。
7. 用户编辑或删除检测任务。

## 6. 核心业务对象

### 6.1 对象关系

```text
Camera 1 ── N CameraSource
CameraSource 1 ── N DetectionTask
DetectionTask N ── 1 Algorithm
```

已明确约束：

- 一个 Camera 至少包含一路 CameraSource。
- 一个 Camera 同时只有一路默认预览源。
- 一个 CameraSource 可以被多个 Detection Task 使用。
- 一个 Detection Task 只绑定一路 CameraSource 和一套 Algorithm。

### 6.2 Camera

| 字段 | 状态 | 说明 |
| --- | --- | --- |
| `camera_id` | 已明确需要 | 系统稳定标识；生成规则未定义 |

| 用户名 | 已明确 | RTSP 连接信息 |
| 密码 | 已明确 | RTSP 连接信息 |
| 默认预览源 | 已明确 | 指向 CameraSource |
| 厂商 | 待确认 | 需求基线列为建议字段，v1.4 无录入或展示入口 |
| 启用状态 | 待确认 | 需求基线列为建议字段，v1.4 无对应操作 |

### 6.5 Algorithm

现有资料能够确认算法至少向任务配置提供：

- `algorithm_id`
- 名称
- 版本
- 参数 schema
- ROI 定义列表

参数 schema 在 v1.4 中演示了数字、单选和布尔类型。原型中的“区域人员检测”“安全着装检测”“通行计数”及其版本、参数和 ROI 均为示例，是否属于首批正式算法待确认。

## 7. Cameras 功能需求

### 7.1 摄像头列表

| ID | 需求 | 状态 |
| --- | --- | --- |
| CAM-01 | 以卡片展示 Camera，不在列表页内展开详情 | 已明确 |
| CAM-02 | 按名称或 IP 实时过滤卡片 | 已明确 |
| CAM-03 | 卡片展示默认预览画面、Camera 名称、IP/端口、聚合连接状态、在线源数/总源数、关联任务数 | 已明确 |
| CAM-04 | 区分“无 Camera”和“搜索无结果”两类空状态 | 已明确 |
| CAM-05 | 点击卡片进入独立详情页 | 已明确 |

Camera 聚合状态的原型规则：

- 所有源均为 `offline`：Camera 显示“离线”。
- 至少一个源不是 `online`，且并非全部离线：Camera 显示“异常”。
- 其他情况：Camera 显示“在线”。

状态来源、探测频率、超时和是否允许更多状态待确认。

### 7.2 新增和编辑摄像头

必填内容：

- 摄像头名称
- IP 地址
- RTSP 端口
- 用户名
- 密码
- 至少一路视频源
- 每路视频源的名称和 URL 后缀
- 唯一的默认预览源

完整地址生成规则：

```text
rtsp://{username}:{password}@{ip}:{port}/{url_suffix}
```

已明确校验：

- 所有上述字段不能为空。
- RTSP 端口输入范围为 `1–65535`。
- 至少保留一路视频源。
- 必须选择一路默认预览源。
- URL 后缀开头的 `/` 在原型保存和生成地址时会被移除。

未明确校验：

- Camera 名称、IP、完整 RTSP 地址是否要求唯一。
- IP 是否只允许 IPv4，是否允许 IPv6、主机名或域名。
- 用户名、密码、名称和 URL 后缀的最大长度及允许字符。
- 同一 Camera 下重复 URL 后缀是阻止、警告还是允许；需求基线只写明“应避免”。
- 保存前是否主动测试连接，以及失败时是否允许保存。

### 7.3 Camera 详情与预览

- 展示名称、IP、RTSP 端口、用户名、密码和默认预览源。
- 展示默认源实时预览，以及 Camera 聚合连接状态。
- 展示所有 CameraSource 的名称、完整 RTSP 地址和连接状态。
- 用户可直接切换默认预览源。
- 用户可开始或停止当前页面预览。
- 停止页面预览不改变 CameraSource 或 DetectionTask 的运行状态。

### 7.4 视频源管理

- 新增或编辑 Camera 时可增加、编辑和移除 CameraSource。
- 移除当前默认预览源后，原型自动将第一路剩余源设为默认预览源。
- 需求基线要求：CameraSource 已被 DetectionTask 引用时阻止删除，并说明关联任务。

v1.4 未实现引用检查，并且使用数组下标关联任务。正式实现必须先定义稳定 `source_id` 及删除约束，不能复制原型的数据关联方式。

### 7.5 凭据处理

现有需求基线明确要求 RTSP 用户名、密码和完整地址明文保存、由 API 原样返回、在前端原样展示，且暂不要求日志脱敏。该要求与通常的凭据安全控制存在冲突，上线适用范围、访问权限和审计要求仍需再次确认；在确认前不能自行改为加密或脱敏，也不能默认该方案已通过安全评审。

## 8. Detection Tasks 功能需求

### 8.1 任务列表

| ID | 需求 | 状态 |
| --- | --- | --- |
| TASK-01 | 展示任务名称、描述、摄像头源、算法名称/版本和状态 | 已明确 |
| TASK-02 | 搜索任务名称、描述、任务 ID、Camera 名称、CameraSource 名称、算法名称和算法 ID | 原型已实现；搜索框提示文案未列出任务 ID，是否保留该搜索字段待确认 |
| TASK-03 | 区分“无任务”和“搜索无结果”两类空状态 | 已明确 |
| TASK-04 | 无任务时提供创建入口 | 已明确 |
| TASK-05 | 点击任务行进入独立详情页 | 已明确 |

### 8.2 创建任务

创建流程：

1. 填写必填的任务名称。
2. 可选填写任务描述，最多 100 个字符。
3. 先选择 Camera，再从该 Camera 下选择一路 CameraSource。
4. 选择一套 Algorithm。
5. 填写由算法 schema 动态生成的参数。
6. 完成算法规定的全部 ROI。
7. 保存任务。

保存成功后，任务默认处于停止状态：

```text
enabled = false
runtime_state = STOPPED
```

用户需要进入任务详情手动启动。

### 8.3 CameraSource 选择

- Camera 选项展示名称和 IP。
- CameraSource 选项展示源名称和当前连接状态。
- 切换 Camera 后，CameraSource 列表随之刷新。
- 没有可用 CameraSource 时，源选择器禁用且不能保存。
- 同一路 CameraSource 可绑定多个任务，当前版本不限制数量。
- v1.4 允许选择离线源并保存；需求基线要求创建或启用前明确提示不可用。具体采用阻止、警告确认还是仅提示，待确认。

### 8.4 算法参数

- 参数字段、类型、默认值和约束由所选 Algorithm 定义。
- 切换 Algorithm 后，参数表单切换为新算法定义，并使用其默认值。
- 编辑任务时回填当前已保存参数。
- 数字参数在原型中校验最小值和最大值，错误时指出字段及合法范围。
- 后端必须再次校验参数，不能仅依赖前端校验。

待确认：

- 正式 schema 支持的完整字段类型、必填、精度、枚举、依赖关系和跨字段校验规则。
- 算法版本是随算法固定、由用户选择，还是由平台自动升级。
- 切换算法后旧参数是否保留为草稿，以及切回旧算法时是否恢复。

### 8.5 ROI 编辑

已明确行为：

- ROI 数量、ID 和标签由算法定义，用户不能新增、删除或改名。
- 用户从 ROI 列表选择一项，在画面上逐点绘制不规则多边形。
- 每个有效 ROI 至少需要 3 个顶点。
- 绘制中支持撤销最后一点、完成和取消。
- 取消重绘时保留原来的已完成 ROI。
- 已完成 ROI 通过整体重绘修改；MVP 不支持拖动单个顶点。
- 所有算法要求的 ROI 完成后才允许保存任务。
- 切换算法后，ROI 列表替换为新算法定义，不沿用不匹配的 ROI。

待确认：

- ROI 编辑画面来自实时流、静态截图还是其他来源。
- ROI 坐标协议、精度、原点、画面比例、旋转和裁剪规则。
- 多边形是否允许自相交、越界、重复点、重合区域或最小面积过小。
- 算法是否可能不要求 ROI；若数量为零，页面和保存规则如何处理。
- ROI 颜色由前端临时分配还是作为任务配置持久化。
- 保存失败或弹窗意外关闭时是否保留草稿。

### 8.6 编辑任务

- 编辑入口位于任务详情页。
- 编辑时回填名称、描述、Camera、CameraSource、Algorithm、参数和 ROI。
- 保存编辑不得自动改变 `enabled` 或当前运行状态。
- 编辑运行中任务后，新配置何时生效尚未明确。v1.4 同时提供“重载”，但未定义保存是否只更新 Desired State、是否自动下发或是否提示存在未应用版本。

### 8.7 任务详情

- 展示任务名称和可选描述。
- 展示任务 ID、Camera/CameraSource、算法 ID/版本和参数摘要。
- 展示实时标注画面、检测结果标签及帧元数据。
- 检测结果框始终显示；“显示 ROI”只控制 ROI 叠加层。
- 展示 ROI 颜色图例。
- 展示任务状态。
- 提供启动/停止、重载、重启、编辑和删除入口。

检测结果的正式字段、刷新方式、延迟、断线状态和错误展示尚未定义。需求基线提出“统一公共字段 + 算法扩展字段”，但协议未冻结。

### 8.8 启动与停止

`enabled` 表示 Desired State：

- 启动：设置 `enabled = true`，任务应运行。
- 停止：设置 `enabled = false`，任务不应运行。
- 不设置暂停状态。
- 系统或 Detector 恢复后，只自动恢复 `enabled = true` 的任务。

`enabled` 与 Actual State 必须分开。v1.4 为展示方便，仅按 `enabled` 映射“运行中/已停止”，不能据此实现生产状态机。

### 8.9 重载

- 仅 `enabled = true` 时可操作；任务停止时按钮禁用。
- 产品语义为保持任务进程运行，重新载入当前已保存配置。
- 操作期间按钮显示忙碌状态并防止重复提交。
- 完成后需要明确反馈结果。

重载是否会重建算法实例、是否会短暂丢帧、超时多久、失败后使用旧配置还是进入错误状态，均待确认。

### 8.10 重启

- 仅 `enabled = true` 时可操作；任务停止时按钮禁用。
- 停止当前算法实例和视频连接。
- 使用当前已保存配置重新启动。
- 操作期间按钮显示忙碌状态并防止重复提交。
- 完成后返回新的运行状态或明确错误。

超时、幂等、重复命令和失败回退规则待确认。

### 8.11 删除任务

- 删除入口位于详情页危险操作区。
- 删除前弹出警告框，显示任务名称并说明不可撤销。
- 确认后删除任务配置、返回列表，并刷新资源数量。

运行中任务是先停止再删除、禁止删除，还是允许异步清理，尚未明确。删除失败、部分成功和并发操作的处理也未定义。

## 9. 状态与数据要求

### 9.1 CameraSource 状态

v1.4 展示：

- `online` → 在线
- `degraded` → 异常
- `offline` → 离线

正式状态集合、状态来源、最近检查时间、错误原因、刷新周期和恢复条件待确认。

### 9.2 DetectionTask 状态

需求基线要求分离：

```text
Desired State：enabled
Actual State：独立的运行状态
```

需求基线曾列出候选 Actual State：`STARTING / RUNNING / RECONNECTING / DEGRADED / STOPPING / STOPPED / ERROR`。该集合被描述为“建议”，因此本文不将其视为已冻结枚举。状态转换、展示文案、颜色、操作可用性和异常恢复策略待确认。

### 9.3 检测结果

需求基线提出以下候选公共字段：

- `task_id`
- `camera_id`
- `source_id`
- `algorithm_id`
- `algorithm_version`
- `frame_id`
- `frame_ts`
- `result_type`
- `objects`
- `metrics`
- `attributes`

不同算法输出协议尚未冻结，上述字段不能直接作为已确认 API 合约。

## 10. 通用交互要求

### 10.1 反馈与异常

- 保存、切换预览源、启动、停止、重载、重启和删除后提供状态消息。
- 表单错误指出修复方式，并关联到具体字段。
- 耗时操作展示忙碌状态并防止重复提交。
- 无数据和搜索无结果使用不同空状态。

v1.4 没有覆盖接口加载、视频加载、保存失败、权限不足、网络中断、命令超时和并发修改页面。这些异常的展示与恢复方式待确认。

### 10.2 弹窗

- Camera 和 DetectionTask 通过弹窗新增或编辑。
- 弹窗可通过取消、关闭按钮、点击遮罩或 `Escape` 关闭。
- ROI 绘制中按 `Escape` 只取消本次绘制草稿。
- 删除任务使用单独的警告弹窗。

是否需要未保存更改确认，以及误触遮罩是否应直接丢弃内容，待确认。

### 10.3 主题与布局

- 提供浅色/深色主题切换。
- 记住主题和桌面侧边栏展开偏好。
- 桌面端侧边栏可折叠为图标栏。
- 窄视口下侧边栏表现为抽屉。
- `Control/Command + B` 切换侧边栏。
- v1.4 在多个断点重排卡片、列表、详情、表单和 ROI 编辑区。

是否承诺手机设备可用、具体支持的浏览器和最低视口宽度，待确认。

### 10.4 可访问性

原型已体现：

- 导航、按钮、弹窗、警告框和状态通知具有语义与可访问名称。
- 交互控件具有键盘焦点样式。
- 状态同时使用文字和颜色/形状表达。
- 支持 `prefers-reduced-motion`。
- ROI 列表和操作按钮可由键盘访问。

ROI 画布点位输入在 MVP 中仅支持指针。正式可访问性标准、目标等级和测试范围待确认。

## 11. 非功能需求

根据仓库现有架构文档：

- 前端通过 FastAPI 管理业务资源。

这些是现有架构基线，具体接口仍需单独设计。

## 12. 已明确需求的验收条件

### 12.1 Camera

1. 填写完整 Camera 字段、至少一路完整 CameraSource 并选择默认源后，可以保存。
2. 缺少任一必填字段、没有视频源或没有默认源时，禁止保存并给出具体错误。
3. 新增和编辑时可以管理多路源，且任一时刻只有一路默认预览源。
4. 列表可以按名称或 IP 过滤，并区分系统无数据与搜索无结果。
5. 详情展示连接信息、默认预览和每路源状态；切换默认源后列表与详情保持一致。
6. 停止当前页面预览不会停止检测任务。

### 12.2 DetectionTask

1. 用户可以绑定一路 CameraSource 和一套 Algorithm，填写合法参数并完成全部必需 ROI 后保存任务。
2. 任务名称为空、描述超过 100 字符、未选择源/算法、参数越界、ROI 少于 3 点或存在未完成 ROI 时，禁止保存并给出具体错误。
3. 新建任务保存后 `enabled = false`，不会自动启动。
4. 编辑任务并保存不会自动改变其 `enabled`。
5. 启动把 `enabled` 设为 `true`；停止把 `enabled` 设为 `false`；系统不存在暂停态。
6. 停止状态下不能重载或重启。
7. 删除前必须显示包含任务名称的二次确认。
8. ROI 显示开关只影响 ROI 叠加层，不隐藏检测结果框。

未明确的异常流程、性能、权限和状态机不纳入当前验收，必须在对应问题确认后补充。
