# 低价值或易碎测试的常见表现

若发现以下情况，应考虑简化、迁移或移除该测试：

- 断言私有状态、私有方法、钩子（hook）调用或内部调用次数。
- 为了复现具体实现细节而模拟（mock）了大多数协作对象。
- 重复测试了已在更合适的层级得到保障的行为。
- 存在的唯一目的是提高测试覆盖率。
- 穷举无实际风险的 null/空值/最小值/最大值组合。
- 在已有合适的专用测试文件的情况下，却新建了测试文件。
- 使用了庞大的快照（snapshot），导致代码审查者往往会盲目更新它。
- 为组件级或集成级测试已能覆盖的行为添加端到端（E2E）测试。
- 使用休眠（sleep）或依赖时间控制，而非确定性的同步机制。
- 依赖测试执行顺序或残留的全局状态。
- 没有明确要保障的行为、契约、风险防范或回归测试目标。

一个有价值的测试应当能简短地回答以下问题：

“这个测试能防止什么样的未来缺陷在未被察觉的情况下发布？”
