# 方案执行门禁

审核显式指定的方案。开始前读取与其直接相关的项目规划、相邻阶段方案和当前代码状态。

## 审核

检查：

* **项目一致性**：是否符合整体规划和实施顺序，与其他任务无冲突、重复或依赖错误。
* **职责边界**：是否错误纳入其他阶段职责，或遗漏当前阶段必须完成的内容。
* **明确性**：需求、接口、数据流、前置条件、实施步骤和验收标准是否足够明确，无需关键假设即可实施。
* **MVP / 过度设计**：是否满足当前模块的最小完整交付；是否为未确认的未来需求提前引入不必要的抽象、扩展层、通用机制或复杂度。
* **可执行性**：方案是否符合当前代码和依赖状态，并形成可实施、可验证的闭环。

优先从代码和现有文档中消除疑问，不把可自行确认的事实交给用户决策。

## 门禁

### PASS

全部检查通过时：

`审核结果：PASS`

简要输出方案职责、关键边界和实施约束。

只有 PASS 后才允许进入代码实施。

### HITL

存在职责冲突、重要不确定性或需要人为决策的问题时：

`审核结果：HITL`

说明阻塞问题及推荐方案，并只向用户询问无法从现有信息确定的决策。

用户确认后：

1. 更新指定方案；
2. 重新完整审核；
3. 未 PASS 前禁止实施。

## 原则

**当前方案应是边界清晰、决策完整、符合项目规划和模块 MVP 的最小完整可交付阶段。不要通过扩大范围或提前设计未来能力来解决当前问题。**
